# HANTER GAMES

تطبيق PWA لمتابعة العادات والأهداف بخطة سنوية واحدة تُعرض باليوم والأسبوع والشهر ونصف السنة والسنة. عربي (RTL) افتراضيًا مع إنجليزية (LTR).

**الحزمة:** React 19 + TypeScript + Vite · Supabase (Auth + Postgres + RLS + Realtime) · Service Worker يدوي · بدون مكتبات واجهة إضافية.

---

## ثلاث نسخ — لا تخلط بينها

| النسخة | أين البيانات؟ | حساب ومزامنة؟ | الحالة |
|---|---|---|---|
| **المعاينة** (Artifact في شات Claude، أو `dist-preview/index.html`) | متصفحك فقط (localStorage) | لا | مبنية ومختبرة في المتصفح |
| **محلي** (`npm run dev` بدون `.env.local`) | متصفحك فقط | لا | نفس الكود؛ يحتاج `npm install` على جهازك |
| **السحابية المنشورة** (مع Supabase واستضافة) | Postgres على Supabase | نعم، بين أجهزتك | **لم تُنشر بعد** — تحتاج الخطوات أدناه بحسابك |

بدون متغيرات Supabase يعمل التطبيق في وضع «هذا الجهاز فقط» أو «العرض التجريبي» (بيانات منفصلة تمامًا).

## التشغيل المحلي (5 دقائق)

المطلوب: Node.js 20.19 أو أحدث.

```bash
npm install
npm test          # اختبارات الحسابات (Vitest)
npm run dev       # http://localhost:5173
```

> ملاحظة صادقة: إصدارات الحزم في `package.json` لم أستطع التحقق منها من سجل npm أثناء البناء (كان محجوبًا). إذا فشل `npm install` بسبب إصدار، شغّل `npm install vite@latest @vitejs/plugin-react@latest vitest@latest` ثم أعد المحاولة.

## ربط Supabase (أقل إجراءات مطلوبة منك)

1. أنشئ مشروعًا على https://supabase.com (الخطة المجانية تكفي للبداية).
2. **SQL Editor** → الصق محتوى `supabase/migrations/20261103000000_init.sql` وشغّله، ثم `supabase/seed.sql` (مكتبة الاقتباسات).
   أو عبر CLI: `npx supabase link --project-ref <ref>` ثم `npx supabase db push`.
3. **Project Settings → API Keys**: انسخ *Project URL* و*Publishable key* (`sb_publishable_...`).
4. أنشئ `.env.local` من `.env.example` والصق القيمتين. **لا تضع أبدًا** الـ secret / service_role key في هذا الملف أو في الواجهة.
5. **Authentication → URL Configuration**: أضف `http://localhost:5173` ورابط موقعك المنشور في *Site URL* و*Redirect URLs* (لرابط الدخول بالبريد).
6. **Database → Replication**: تأكد أن جداول التطبيق مضافة إلى `supabase_realtime` (الـ migration يحاول ذلك تلقائيًا).
7. `npm run dev` → سجّل حسابًا → اختر تاريخ بداية سنتك.

## النشر (HTTPS مطلوب للتثبيت كتطبيق)

Vercel أو Netlify أو Cloudflare Pages:
- Build command: `npm run build` · Output: `dist`
- Environment variables: `VITE_SUPABASE_URL` و`VITE_SUPABASE_PUBLISHABLE_KEY`
- لا حاجة لقواعد إعادة توجيه: المسارات تعمل بالـ hash (`#/day/2026-11-03`)، فالرابط المباشر يعمل بعد إعادة التحميل على أي استضافة.
- بعد النشر أضف رابط الموقع في إعدادات Auth (الخطوة 5).

## البنية

```
src/domain/     منطق خالص بلا واجهة — مصدر واحد لكل الحسابات
  dates.ts        أيام تقويمية كنصوص YYYY-MM-DD (لا انجراف بسبب المنطقة الزمنية)
  periods.ts      سنة تخطيطية، شهور من تاريخ البداية الأصلي، أنصاف، أسابيع حقيقية، نطاقات [start, end)
  schedule.ts     العادات بإصدارات جداول + المهام → «فرص» مقيّمة بحالة واحدة
  progress.ts     الالتزام / التقدم في الخطة / تحقق النتيجة + تجميع الأهداف من الأبناء المباشرين
  trend.ts        مقارنة نافذتين + «العودة بعد انقطاع»
  rewards.ts      XP مشتق من مفاتيح فريدة (لا يمكن جمعه بالتراجع/الإعادة)
  quotes.ts       اختيار يومي ثابت ومتسق بين الأجهزة
src/data/       مستودع محلي + Supabase، متجر بصف انتظار ومعالجة تعارض
src/ui/         الصفحات والمكونات
supabase/       migrations + seed + اختبارات SQL
quotes/         مكتبة الاقتباسات ومصادرها
docs/PSYCHOLOGY.md   قرارات التصميم ومصادرها وحدود الأدلة
STATUS.md       حالة المشروع ونقطة المتابعة
```

### كيف تُحسب الأرقام (مختصر)
- **مساهمة الفرصة** = `min(المنفّذ ÷ المستهدف, 1)` بعد جمع جلسات اليوم؛ الثنائية 0 أو 1.
- **الالتزام** = Σ(مساهمة × وزن) ÷ Σ(أوزان) للفرص التي انتهى وقتها فقط. اليوم الحالي يُحتسب بعد انتهائه. غير المسجّل يبقى في المقام بلا رصيد، و«تغطية التسجيل» تُعرض منفصلة.
- **التقدم في الخطة** يشمل المستقبل؛ و«المتوقع حتى الآن» = حصة العمل المخطط الذي انتهى وقته (غير خطي).
- **تحقق النتيجة** من نتيجة يسجلها المستخدم فقط.
- عادة «3 مرات أسبوعيًا» فرصة واحدة لكل أسبوع مستهدفها 3 جلسات، تُنسب لآخر يوم في أسبوعها حتى لا تُحتسب مرتين عند تجميع الشهور. أيام الراحة/الإيقاف داخل الأسبوع تقلّل المستهدف بالتناسب.

### وضع عدم الاتصال
- قراءة: الواجهة (Service Worker) + آخر نسخة بيانات محفوظة مع عرض وقت آخر مزامنة.
- كتابة: **ممنوعة في الوضع السحابي أثناء انقطاع الإنترنت** (قراءة فقط، مع شارة واضحة). اختيار مقصود: لا يوجد صف انتظار للكتابة دون اتصال في هذه النسخة.
- عند فشل شبكة أثناء الاتصال: يبقى التعديل في صف إرسال محفوظ ويُعاد إرساله بنفس معرّف العملية (لا تكرار).

### الإشعارات
تذكيرات **داخل التطبيق فقط** (مع وقت هدوء وحد يومي). إشعارات الخلفية والتطبيق مغلق **غير منفّذة**.

## ملفات التثبيت (APK للتلفون و EXE للابتوب)

الـ Workflow `Build app packages` يبني تلقائيًا مع كل تحديث على `main`، ويضيف الملفين إلى صفحة **Releases** في الـ repo:

| الملف | الجهاز | ملاحظات التثبيت |
|---|---|---|
| `HANTER-GAMES.apk` | أندرويد | اسمح بالتثبيت من «مصادر غير معروفة» لمتصفحك أو مدير الملفات. النسخة موقّعة بمفتاح debug؛ عند تحديث من بناء آخر قد يطلب الجهاز حذف القديمة أولًا (بياناتك في Supabase لا تتأثر). |
| `HANTER-GAMES-Setup.exe` | ويندوز | غير موقّع رقميًا، فسيظهر تحذير SmartScreen: «More info» ← «Run anyway». |

- الدخول داخل التطبيقين بالبريد وكلمة المرور (رابط الدخول السحري يعمل في نسخة المتصفح فقط).
- البيانات واحدة بين التلفون واللابتوب ونسخة المتصفح، لأنها كلها تقرأ من نفس Supabase.
