# تطوّري: تطبيق شخصي للتطور والأفكار والمال والحسابات

تطبيق ويب شخصي لمالك واحد، بواجهة عربية RTL، مناسب للموبايل أولًا، ويعمل على الكمبيوتر أيضًا.
يجمع: رحلة تطور بالمستويات، وبنك للأفكار والتحديات، ومتابعة مالية بمساحات منفصلة، وفهرس للحسابات الرقمية (بدون كلمات مرور).

> **الحالة الصادقة:** الكود مكتوب ومُختبر محليًا (منطق الأعمال + سيناريوهات متصفح). **لم يُنشر بعد**، ولم يُختبر مع مشروع Supabase حقيقي. التفاصيل في قسم «ما تم التحقق منه».

## 2. التشغيل المحلي

يحتاج Node.js 20 أو أحدث للاختبارات، ومتصفحًا حديثًا.

```bash
# تشغيل الواجهة (لا تفتح index.html مباشرة من الملفات؛ ES Modules تحتاج خادمًا)
cd personal-app
python3 -m http.server 8080
# ثم افتح http://localhost:8080
```

بدون إعدادات Supabase يعمل التطبيق على **هذا الجهاز فقط** (البيانات في localStorage). هذا يكفي للتجربة.

### الاختبارات

```bash
node --test personal-app/tests/*.check.mjs
```

| الملف | ماذا يغطي |
|---|---|
| `domain.check.mjs` | المال والتواريخ والتقدم والترقية والبنك والديون والميزانيات والالتزامات وصافي الثروة والنسخ |
| `sync.check.mjs` | المزامنة بخادم وهمي يطابق قواعد `save_user_state`: تعارض، إعادة إرسال بنفس المعرّف، انقطاع بعد الكتابة |
| `finance-edit.check.mjs` | تعديل البيانات الوصفية للعمليات، والحذف المحظور، وسجل التدقيق |

### اختبارات المتصفح (Playwright)

تحتاج متصفح Chromium وحزمة Playwright (لا تُضاف إلى package.json؛ تُثبَّت محليًا فقط):

```bash
cd personal-app
npm i --no-save playwright
# في نافذة أخرى: شغّل الخادم على 8080 (انظر قسم التشغيل المحلي)
APP_URL=http://127.0.0.1:8080 node tests/browser/smoke.cjs    # المستوى والمكافأة والبنك والحسابات والمال (شاشة 390px)
APP_URL=http://127.0.0.1:8080 node tests/browser/smoke2.cjs   # الديون والميزانية والالتزامات والنسخ الاحتياطي والاستعادة
APP_URL=http://127.0.0.1:8080 node tests/browser/smoke3.cjs   # تسجيل الدخول والمزامنة الأولى (طلبات Supabase مُحاكاة)
APP_URL=http://127.0.0.1:8080 node tests/browser/smoke4.cjs   # نقاط النمو، البنك المتقدم، توزيع الهدف، المطابقة، تعديل العملية، الحسابات الرقمية
```

## 3. ربط السحابة (Supabase)

> ملاحظة: لم أتمكن من التحقق من خطط Supabase الحالية (انظر قسم 8). تحقق من الحدود الرسمية قبل الاعتماد عليها.

1. **أنشئ مشروعًا جديدًا** في Supabase مخصصًا لهذا التطبيق (لا تستخدم مشروع الألعاب).
2. **SQL Editor** → الصق محتوى `supabase/schema.sql` وشغّله.
3. **Authentication → Users → Add user**: أنشئ حساب المالك بالبريد وكلمة مرور قوية.
4. انسخ معرّف المستخدم (UUID) ونفّذ:
   ```sql
   insert into public.app_owner (user_id) values ('<UUID-الخاص-بك>');
   ```
5. **Authentication → Sign In / Providers**: أوقف التسجيل العام (Allow new users to sign up). حتى لو بقي مفتوحًا، أي مستخدم جديد ليس في `app_owner` لن يقرأ ولن يكتب أي بيانات، لأن RLS ودالة الحفظ تتحققان من ذلك.
6. **Project Settings → API**: انسخ *Project URL* و*publishable / anon key* وضعهما في `config.js`:
   ```js
   window.PERSONAL_APP_CONFIG = {
     supabaseUrl: 'https://xxxx.supabase.co',
     supabaseAnonKey: 'sb_publishable_...',
   };
   ```
   **ممنوع** وضع `service_role` key في أي ملف من هذا المستودع. المفتاح العام آمن للواجهة لأن الحماية في قاعدة البيانات (RLS)، لا في إخفاء المفتاح.
7. افتح التطبيق، سجّل الدخول. أول حفظ ينشئ نسخة السحابة.

### كيف تعمل المزامنة

- الحالة كلها كائن JSON واحد لكل مالك، مع رقم **إصدار** (`version`).
- كل حفظ يقول للخادم «أكتب إذا كان الإصدار ما زال X». إذا تغيّر من جهاز آخر يُرفض الحفظ (P0409)، فيظهر **قرار تعارض** ولا يُستبدل شيء بصمت.
- كل طلب له معرّف (`request id`) يُعاد استخدامه عند إعادة المحاولة، فلا تتكرر الكتابة إذا ضاع الرد بعد نجاح الحفظ.
- التعديلات تُحفظ على الجهاز فورًا. عند الانقطاع تبقى محفوظة محليًا وتُرسل لاحقًا، وتظهر الحالة في الشريط العلوي.
- الدخول بالبريد وكلمة المرور. الجلسة (الرموز) تبقى في localStorage حتى تسجّل الخروج.

### تسجيل الخروج

يمسح البيانات المحلية والجلسة من الجهاز، ويعرض نسخة احتياطية أولًا إذا كانت هناك تعديلات لم تُرسل. السحابة لا تتأثر.

## 4. النشر

التطبيق ملفات ثابتة يمكن استضافتها على أي خدمة ثابتة. اخترت عدم تفضيل مزود بعينه قبل التحقق من حدوده الرسمية. الخيارات الشائعة: Cloudflare Pages، Netlify، GitHub Pages.

- يجب أن يكون الموقع على **HTTPS** ليعمل Service Worker والتثبيت كتطبيق (`localhost` مسموح للتجربة).
- لا توجد قواعد إعادة توجيه خاصة: التطبيق يعمل بالـ hash (`#/money`).
- بعد النشر أضف رابط الموقع في Supabase: **Authentication → URL Configuration** (Site URL و Redirect URLs) إن استخدمت روابط البريد لاحقًا.
- لا تنشر `config.js` مع مفتاح `service_role` أبدًا (لن تجده هنا).

## 5. البيانات والقواعد الأساسية

| الموضوع | القاعدة المطبقة |
|---|---|
| الترقية | تكتمل كل التحديات النشطة بشرطها الفعلي، لا عند تقريب النسبة. التحدي المتوقف لا يكتمل. المستوى الفارغ لا يكتمل. |
| النسبة المعروضة | للعرض فقط. الترقية تُفحص بالشرط المنطقي (boolean) |
| المكافأة والشارة | تُمنحان مرة واحدة عند إكمال المستوى، وتُحفظان في السجل بتاريخهما |
| المستويات المكتملة | نسخة ثابتة (snapshot) لا تُعدَّل. تغيير عدد المستهدف لا يحذف شيئًا |
| بنك الأفكار | قوالب فقط. الإضافة إلى مستوى تنشئ نسخة مستقلة، وتعديل القالب لا يغيّرها |
| الاستبدال | يحفظ القديم مع تقدمه وسببه. البديل يبدأ من الصفر |
| الدرجات | الأعلى = وضع أفضل، للقوة والضعف معًا. إكمال التحديات يُعرض منفصلًا عن التقييم الذاتي |
| الحساب المالي | الرصيد الافتتاحي ليس دخلًا. التحويل بين الحسابات ليس دخلًا ولا مصروفًا (الرسوم فقط مصروف) |
| الديون | السداد يفصل الأصل عن الرسوم/الفوائد. قبض قرض ليس دخلًا. |
| الالتزامات المجدولة | لا تغيّر الرصيد حتى يُسجَّل الدفع. الدفع الجزئي يترك الباقي مستحقًا. التعديل يؤثر في المستقبل فقط |
| المطابقة | تُظهر الفرق فقط. لا يتغير الرصيد إلا بتسوية تُنشأ صراحة |
| صافي الثروة | حسابات وديون مسجلة فقط، ويعرض نطاقه. لا يعرض إجماليًا إذا غاب سعر صرف |
| الفائض | يُسمى «الفائض النقدي التشغيلي» وليس «صافي ربح محاسبي»، لأن النظام لا يطبّق محاسبة الاستحقاق |
| أسعار الصرف | يدخلها المستخدم يدويًا بتاريخ. السعر المسجَّل لا يُستبدل تلقائيًا، فالعملية القديمة تبقى بسعرها |
| الحسابات الرقمية | لا تحفظ كلمات المرور ولا أكواد التحقق ولا الرموز. أي حقل بهذه الأسماء يُرفض |

## 6. الأمان والخصوصية

- **تحقق الملكية في الخادم:** RLS على جدول الحالة، ودالة `is_owner()` ترفض أي مستخدم ليس المالك. الكتابة عبر دالة واحدة فقط، ولا توجد سياسة كتابة مباشرة.
- **مفتاح الواجهة:** publishable/anon فقط. لا أسرار في المستودع.
- **المرفقات:** الصور (الإيصالات، أدلة التحديات، صورة الملف الشخصي) تُضغط في المتصفح وتُحفظ داخل الحالة نفسها، فتخضع لـ RLS ولا تحصل على روابط عامة.
- **النسخ الاحتياطي:** ملف JSON يحتوي كل شيء بما فيه المرفقات. **أي شخص يملكه يرى بياناتك**، احفظه في مكان آمن.
- **لا تتبع ولا تحليلات:** التطبيق لا يرسل بيانات إلى أي خدمة تحليلات أو تتبع أو أخطاء خارجية. الأخطاء غير المتوقعة تُطبع في console المتصفح فقط.
- **التوصية:** فعّل المصادقة الثنائية لحساب Supabase نفسه من لوحة المشروع، وتحقق من توفرها في خطتك.
- **قيود معروفة:** رموز الجلسة في localStorage، لذلك أي كود طرف ثالث داخل الصفحة يُعد خطرًا. التطبيق لا يحمّل أي سكربتات خارجية.

## 7. ما لم يُنفذ (صراحة)

- **الإشعارات في الخلفية:** غير موجودة. التذكيرات داخل التطبيق فقط إن أضفتها لاحقًا.
- **الربط البنكي واستيراد كشوف الحسابات:** غير موجود عمدًا (طلب النسخة الأولى يدويًا فقط).
- **تعديل مبلغ أو حساب عملية موجودة:** غير مسموح. التصحيح بالحذف (إن لم يكن لها ما يعتمد عليها) وإعادة التسجيل، أو بالتسوية.
- **إعادة تقييم العملات للأرصدة الحالية:** غير موجود. صافي الثروة يُحسب بأحدث سعر مسجل.
- **المرفقات في مخزن ملفات منفصل:** الصور داخل الحالة نفسها. هذا يحد حجم البيانات بسعة localStorage على الجهاز، وبحجم الصف في Postgres على الخادم. إذا كبرت المرفقات، الخطوة التالية مخزن ملفات مستقل.
- **تجريب البيانات (sample data):** غير موجود.
- **توزيع الهدف الكبير:** يدعم أجزاء رقمية فقط في الواجهة. البنية في المنطق تدعم التحدي المركب أيضًا.
- **التحديث الفوري بين الأجهزة:** غير موجود (لا Realtime). التعديل من جهاز آخر يظهر عند فتح التطبيق أو عند الضغط على «مزامنة الآن»، والتعارض يُكتشف عند الحفظ أو السحب.

### لم يُتحقق منه

- **Supabase الحقيقي:** لم يُنشأ مشروع، ولم يُشغَّل `schema.sql` على Postgres (لا خادم Postgres متاح في بيئة البناء). منطق المزامنة مختبر بخادم وهمي يحاكي القواعد، لا بالخادم نفسه.
- **المزامنة بين جهازين حقيقيين.**
- **التثبيت كتطبيق وعمل Service Worker على HTTPS.**
- **حدود الخطط الحالية:** حاولت التحقق من الصفحات الرسمية لـ Supabase وCloudflare وBitwarden وProton Pass، فتعذّر الوصول إليها من بيئة البناء (فشل حل أسماء النطاقات، وقد طلبت السماح بها فرُفض). **لذلك لا أستطيع تأكيد أي رقم من أرقام الخطط أو الحدود أو الأسعار.** الروابط الرسمية للتحقق:
  - https://supabase.com/pricing
  - https://developers.cloudflare.com/pages/platform/limits/
  - https://bitwarden.com/help/password-manager-plans/
  - https://proton.me/pass/pricing
- **مدير كلمات المرور:** الافتراضي Bitwarden برابط `https://vault.bitwarden.com/` من معرفتي العامة، **غير مُتحقَّق منه** من الوثائق الرسمية في بيئة البناء. تحقق من الرابط والخطة المجانية قبل الاعتماد، وغيّره من الإعدادات إن لزم.

## 9. تحديث البيانات لاحقًا

رقم `schemaVersion` في الحالة يحدد الإصدار. النسخ الاحتياطية تحمل الإصدار، والتطبيق يرفض ملفًا أحدث منه بدل أن يفسده. عند تغيير الشكل مستقبلًا تُضاف دالة ترحيل في `src/core/state.js`.
